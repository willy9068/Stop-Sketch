* 컨셉·아트 결정
   * 컨셉 후보는 스케치북 세계, 서사는 지워지는 세계, 캐릭터는 물방울 모양 낙서 생물(교체 가능), 아트·UI는 고양이와 스프 참고, 사운드는 후순위
   * 자동 달리기로 하면 물감을 먹으러 가거나 퍼즐을 풀기 어렵고, 색이 여러 개면 선택할 시간이 촉박하다는 문제를 제기 → 맥스앤매직마커처럼 시간 정지 후 그리기(횟수·시간 제한)를 제안하셨고 코어로 확정
   * 고양이와 스프 스크린샷 3장을 보고 모바일 세로 UI는 쓰지 않기로 하고 아트·UI 스타일만 가져감. PC 16:9 가로 화면, 배경은 연한 베이지, 선·잉크·캐릭터는 진하게
   * 2D 횡스크롤, 배경 소품은 최소로, 물리 적용
* 레퍼런스 조사
   * The Magic Ink URL로 직접 플레이하려 했으나 접속 불가(이후 스토어에서 내려간 것 확인) → 스크린샷 3장으로 아트·UI 참고점 정리(상단 한 줄 HUD, 잉크 선택 외곽선, 튜토리얼 연출)
   * 레퍼런스 조사 가이드에 조사한 게임들의 핵심 재미 요소 추가
   * 성과 수치·부진작 조사표 작성 후 2차 조사: 같은 장르만 남기고 다른 장르(Poly Bridge, Draw Climber 등)는 제외
   * 가장 가까운 게임 발견: Lineguard(자동 달리기 + 그리는 동안 감속 + 잉크 물리 성질), Inkrunner(공책 위 자동 이동)
   * 직접 확인: Inkrunner 플레이(색별 효과·함정이 없어 단조로움), 맥스 앤 더 매직 마커(정지 횟수·시간 제한 없음), 커비 캔버스 커스(그리는 동안 시간이 흐름), Draw(퍼즐은 쉽지만 그림체·직관성 호평)
   * 차별점 정리: D1 완전 정지 + 횟수 제한을 앞에, D2는 "색 연쇄" → "색마다 다른 물리 성질을 주고 이용"으로 바꿈
   * 가제를 "잉크 런"에서 "스톱 앤 스케치"로 확정 (같은 이름 게임이 많아서), 폴더·파일 이름도 변경
* 데모 1일차 구현 (Claude Code 활용)
   * 자동 달리기 + 마우스로 그린 선이 물리 발판이 됨 + 시간 정지(구간당 3회) + 잉크 게이지
   * 시간 정지 방식 3가지 비교 기능(A 완전 정지 / B 슬로 모션 0.3배 / C 정지 + 3초 제한), 단일 HTML 제출본 빌드(외부 요청 0), 자동 테스트·물리 시뮬레이션
* 직접 플레이 후 조작 결정

   * 점수 공식 대신 조건 3개(목표 시간 · 수집 별 모두 · 시도 횟수)를 만족한 수만큼 별 0~3개, 하나도 못 채우면 빈 별 0개

   * 발사기·투사체, 색 효과 세기를 레벨 툴에서 구간마다 조절

* 의견:
선행작인 커비 캔버스 커스, 그리고 오늘 2차 조사에서 찾은 Lineguard·Inkrunner가 이미 "선 그리기 + 자동 이동", "색별 물리 성질"을 하고 있어서, 기본 콘셉트만으로는 차별이 되지 않습니다. 그래서 차별점을 시간 완전 정지 + 횟수 제한(D1)에 먼저 두고, 색마다 다른 물리 성질(D2)은 D1과 묶여 "멈춘 동안 어떤 성질을 어디에 쓸지 설계"할 때 차이가 생기도록 정리했습니다. 1일차 데모를 직접 플레이해 보고 달리며 그리기 허용, 선 사라짐, 벽에서 뒤로 돌기, 점프 삭제로 조작을 고쳤고, 정지 방식은 A(완전 정지)로 확정했습니다. 다만 색 잉크 3종과 구간 2~4는 오늘 막 구현해 아직 직접 플레이하지 않았기 때문에, D2가 실제로 "내가 설계했다"는 느낌을 주는지는 확인 전입니다. 다음은 구간 2~4를 플레이해 색 효과 세기와 배치를 레벨 툴로 고치고, 지우개 추격을 넣어 압박과 정지 횟수의 균형을 보겠습니다.

본인 경험 및 의견 (Pass/Fail 3요소)

* ① 직접 시도한 것: The Magic Ink를 URL로 플레이하려 함(접속 실패), 스크린샷 6장(고양이와 스프, Magic Ink) 분석 / 1일차 데모를 직접 플레이하며 정지 방식 A(안전하게 그림)와 B(빨리 그려야 하는 긴장감)를 비교 / Inkrunner·맥스 앤 더 매직 마커·커비 캔버스 커스·Draw 직접 확인 / 레벨 툴로 구간 1을 직접 고침 / ComfyUI로 이미지 1·2차 생성 `[아트 스타일을 직접 그려보거나 시험한 것이 있으면 추가]`
* ② 겪은 어려움:
   * 자동 달리기 방식에서 물감을 먹으러 가거나 퍼즐을 풀기가 어렵고 색을 고를 시간이 촉박함 → 시간 정지 후 그리기로 해결
   * 처음에는 멈춰야만 그릴 수 있어 쉬운 구간도 정지를 써야 했음 → 달리며 그리기 허용으로 해결 `[실제로 어떻게 느꼈는지 본인 말로]`
   * B(슬로 모션)는 나중에 지우개 압박과 겹치면 너무 어려워질 것 같아 고민 → A로 확정
   * The Magic Ink는 접속이 안 되고 스토어에서도 내려가 시스템 확인 못 함(미해결) → 대신 Lineguard·Inkrunner를 가장 가까운 비교 대상으로 둠
* ③ 실무 적용성 판단: 그리기 퍼즐은 성공작이 적지만 재미 자체는 있어 보여 차별성으로 보셨음. 정지 횟수 + 달리며 그리기 조합은 직접 플레이로 방향을 잡았고, 색 잉크가 재미있는지는 플레이 전이라 확신하기 이르다 `[본인 판단으로 보충]`

느낀 점

* 판단력: 코어를 정하기 전에 "자동 달리기에서 물감을 고르고 먹으러 갈 시간이 있는가"라는 문제를 먼저 짚으셨고, 이게 시간 정지 도입으로 이어졌다. 다음에는 조작 방식의 문제를 아이디어 단계에서 더 일찍 확인한다
* 기획자로서 중요한 것: 선택 시간이 부족한 문제는 속도를 늦추는 것이 아니라 "멈출 수 있는 횟수"를 자원으로 만들어 전략으로 바꾸는 방향으로 풀 수 있다. 모바일 UI는 그대로 쓰지 않고 PC에 맞게 다시 설계해야 한다
